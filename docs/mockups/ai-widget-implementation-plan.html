The rating is only accepted once the chat has ended (conversation_state = 'end_confirmed'), and the comment is trimmed and capped.

The check in guest.routes.ts, before any model call

const IDLE_MS = 15 * 60_000;
const since = (t) => t ? Date.now() - new Date(t).getTime() : Infinity;

if (visitor.handled_by_user_id && since(visitor.handled_at) >= IDLE_MS)       // staff went quiet
  await visitorService.setHandoff(tenantDb, visitor.id, null);
if (visitor.handoff_requested_at && since(visitor.handoff_requested_at) >= IDLE_MS) // nobody joined
  await visitorService.expireHandoverRequest(tenantDb, visitor.id);

if (humanActive(visitor) || waitingForHuman(visitor)) {
  // store the user row, unread+1, SSE handoff/handover, [DONE] — no RAG, no LLM, no credits
}
  • Detecting "I want a person": the existing conclusion judge (judgeConclusion, already a separate call) gains a wants_human boolean. It's a separate call from the reply on purpose: a hidden instruction inside the reply gets dropped on busy turns and by the fallback model. Only when wants_human is true, and handover is on for the widget, does the server set handoff_requested_at and send the fixed "I've asked the team to join" line as its own message.
  • The AI never offers a person: the system prompt says not to suggest contacting the team, and no chip may offer it. Handover depends only on what the visitor writes.
  • History sent to the model maps agent → model, so after Resume the AI treats staff replies as its own side.
  • chat-summary.worker saves { text, topics, next_step } into summary when it generates the email, and labels agent turns ("Advisor (Alex):") in the transcript it summarises.
  • Contact card heading in guest.routes.ts:354: "Want a copy of this conversation?" → "Want a summary of this conversation?".

8 · Phases, each shippable

  1. Inbox takeover UI on mock data. Done; still to commit.
  2. Navigation (frontend only). Menu order, Contacts → Visitors, widget page via the Inbox Widget button, Settings item removed with a redirect. Can ship now; it needs no backend.
  3. Takeover backend. Migrations, agent role, the handoff check with 15-minute idle, the dashboard endpoints, history mapping. Switch the Inbox from mock to real.
  4. Widget receives staff replies. Agent bubbles, the poll, the handoff event, "Alex is replying".
  5. Visitor asks for a person. wants_human in the judge, handoff_requested_at, waiting card, "Wants a person" in the Inbox, 15-minute expiry, staff notification (see open questions).
  6. Ratings and summary. POST /guest/rating, the rating card, summary storage in the worker, contact card wording.
  7. Visitor detail page. New layout, Open conversation, email-only header, Chat summary and Activity timeline cards.

Checks for every phase: backend tsc --noEmit; frontend tsc and eslint; you run the migrations and DB tests locally. Backend tests to add: the handoff check skips the LLM and billing, a spoofed role is still stored as agent, the agent CHECK rejects a missing sender, both 15-minute expiries, a rating before the chat has ended is refused, and wants_human is false for "thanks, that's all".

9 · Risks and open questions

ItemRisk / questionProposal
question Staff notificationWhen a visitor asks for a person, who hears about it and how? Today nothing outside the Inbox would show it.v1: "Wants a person" flag and unread in the Inbox, plus an entry under the notification bell for every org member. Email or push later.
question Office hoursWhat should the visitor see when they ask for a person outside office hours?The waiting card says when the team is back, and the AI keeps answering in the meantime.
question Widget switch permissionAny member can pause the widget today; GlobalyOS limits it to admins and owners.Your call. Takeover stays open to every member either way.
question Other routes to the widget pageThe portal's "AI assistant" tile also links to /business/ai-widget, so the Inbox button isn't literally the only way in.Keep the tile (it's a shortcut, not a menu item), or point it at the Inbox. Your call.
question Summaries without an emailSummaries are only generated for visitors who gave an email, so most cards would say "no summary".Generate one for every ended chat (costs one model call each), or show "No summary — the visitor didn't ask for one".
Judge misreads intent"Is there a person I can email?" isn't a handover request, but it might be read as one.Test phrases for the judge, both should-hand-over and shouldn't; the 15-minute expiry limits the damage either way.
Takeover while the AI is streamingThat AI reply still lands after the takeover.Accepted for v1; the "joined" line makes the order clear.
Derived timelineWith single columns, an earlier takeover that was later handed back only survives in the transcript; repeated handover requests show only the latest.Good enough for v1. Add an events table if the team needs a full audit trail.
Off means offPausing the widget also stops chats a person has taken over.The Inbox banner says so.
Rating abuseThe rating endpoint is public.Requires an ended chat, one rating per conversation, the existing per-key-and-IP rate limit.
ConsentThe summary email has no unsubscribe link and the contact card has no privacy notice (already an open item).Settle it before the summary card makes summaries more prominent.

Left out of v1

  • Internal notes, typing indicators, "agent is viewing", read ticks, reactions and edit/delete on AI chats, visitor-side attachments.
  • The AI handing over by itself (low confidence, loop cap). Handover is visitor-initiated only.
  • WhatsApp and Instagram (shown as Coming soon), priority, tags, snooze, tickets, a rating analytics dashboard.
