Mockup for review; nothing is built. When a visitor in the institution's own country asks about applying, studying or visiting, the widget suggests the branch nearest to them. Their approximate location (country and state) comes from two headers Cloudflare adds to each request, and is matched against each branch's state and country. No maps, no coordinates. Example data: a fictional Australian university with three campuses.

How can I help you today?

Who counts as domestic: the visitor's location country, from the headers, matches the country the institution's branches are in. If they told the assistant their nationality and it differs (for example a student from Nepal living in Melbourne), they're treated as international, as today.

When it shows: once per chat, on a reply to a message about applying, enrolling, studying, campuses, visiting or "near me". Only branches the system has placed on the map are considered. If no branch is within the visitor's country, nothing shows.

How "nearest" is chosen: a branch in the visitor's state ("Campus in your state"), else the institution's primary branch in that country ("Our main campus"). No distance is shown, because none is known.

"Get directions" opens Google Maps in a new tab with the branch's written address (a plain link, no Maps API). "See all campuses" lists every branch, best match first.

Branches need a state to be suggested

Matching uses the state and country already on each branch. A branch with no state can still be the main-campus fallback, but never "in your state", so it's flagged here. Use the full state name ("Victoria"), as Cloudflare sends it.
